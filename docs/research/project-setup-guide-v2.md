# Project Setup Guide V2 Research

# Purpose

This document records the reasoning behind the repository structure, TBP model, spec model, milestone lifecycle, and documentation contract model.

# Status

Research / setup rationale.

# Findings

- TBPs should define methodology, not concrete tasks.
- Specs should define behavior and invariants.
- Milestones should sequence work.
- Issues should define concrete execution requests.
- Foundational TBPs are useful for meta-structure work.
- Lightweight issue templates are useful for slow-changing repository processes.
